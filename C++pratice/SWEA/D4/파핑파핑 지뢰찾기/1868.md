# 파핑파핑 지뢰찾기

* 링크: SWEA 1868 - 파핑파핑 지뢰찾기
* 난이도: D4
* 카테고리: BFS

## 문제 요약

`N x N` 크기의 지뢰찾기 보드가 주어진다. 지뢰(`*`)가 아닌 칸을 전부 열기 위해 최소 몇 번 클릭해야 하는지 구하기. 지뢰찾기 규칙상, 주변 8방향에 지뢰가 하나도 없는 칸(값이 0인 칸)을 클릭하면 그 주변 칸들이 자동으로 한꺼번에 열린다.

## 핵심 아이디어

**미리 계산**: 지뢰가 아닌 모든 칸에 대해 주변 8방향에 지뢰가 몇 개 있는지(`cnt[x][y]`)를 먼저 전부 구해둔다.

**0칸부터 우선 클릭**: `cnt[x][y] == 0`인 칸은 주변 8칸이 모두 안전하다는 게 이미 확정된 상태다. 그래서 이 칸을 클릭하면 지뢰찾기 규칙상 주변 8칸이 한꺼번에 열린다. 그러므로 0인 칸을 발견하면 먼저 클릭(`click++`)하고 `BFS`로 그 주변을 연쇄적으로 열어나간다.

**연쇄(BFS)**: `BFS(sx, sy)`는 0인 칸에서 시작해서, 주변 8방향으로 열려있지 않은 칸을 전부 `opened` 처리한다. 이때 새로 연 칸의 값도 0이면(`cnt[nx][ny] == 0`), 그 칸도 자기 주변 8칸이 모두 안전하다는 뜻이므로 큐에 넣어서 또 그 주변을 연다. 값이 1 이상인 칸은 열리기만 하고 더 퍼지지 않는다(큐에 넣지 않음). 이렇게 하면 0인 칸들이 서로 사슬처럼 이어진 하나의 "덩어리"가 한 번의 클릭만으로 전부 열리게 된다.

**남은 칸은 하나씩**: 모든 0칸 덩어리를 다 펼치고 나면, 어느 0칸 덩어리에도 인접하지 않아서 아직 열리지 않은 칸들이 남을 수 있다. 이런 칸들은 자동으로 열릴 방법이 없으므로 하나씩 직접 클릭해야 한다(`cnt[x][y] != 0 && !opened[x][y]`인 칸마다 `click++`).

결국 최종 답은 **(0칸 덩어리의 개수) + (끝까지 자동으로 안 열린 칸의 개수)** 이고, 코드에서는 이 둘을 하나의 `click` 변수에 같이 누적해서 구한다.

## 막혔던 부분 / 실수

* 처음에 `queue`에서 꺼낸 값을 `auto [x, y] = q.front();`처럼 구조분해 선언(C++17)으로 받으려 했는데, 이 프로젝트가 쓰던 컴파일러(MinGW g++ 6.3.0)가 너무 오래된 버전이라 구조분해 선언 문법 자체를 지원하지 않아서 "expected unqualified-id before '[' token" 오류가 계속 났다. 컴파일러를 최신 GCC로 업그레이드해서 해결했다.
* 반복문에서 `for (int x = 0; x < N; i++)`처럼 증가시켜야 할 변수(`x`)가 아니라 바깥 테스트케이스 루프의 `i`를 증가시킨 실수가 있었다. `x`가 영원히 0에 머물러 무한 루프에 빠지는 문제였고, `i++`를 `x++`로 고쳐서 해결했다.

## 시간복잡도

* 시간: O(N²) (지뢰 개수 계산, BFS, 남은 칸 세기 모두 전체 칸을 한 번씩 순회)
* 공간: O(N²) (`board`, `cnt`, `opened` 배열)
