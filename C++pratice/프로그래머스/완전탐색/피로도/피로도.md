# 피로도

* 링크: 프로그래머스 - 피로도 (Lv.2)
* 난이도: Lv.2
* 카테고리: 완전탐색

## 문제 요약

현재 피로도 `k`와 던전 목록(각 던전은 [최소 필요 피로도, 소모 피로도])이 주어진다. 던전은 최소 필요 피로도 이상일 때만 탐험할 수 있고, 탐험하면 소모 피로도만큼 피로도가 줄어든다. 각 던전은 최대 한 번만 탐험 가능할 때, 최대한 많은 던전을 탐험하려면 몇 개까지 갈 수 있는지 구하기.

## 핵심 아이디어

던전을 방문하는 순서에 따라 최종적으로 탐험 가능한 개수가 달라지므로, 모든 순서를 완전탐색(DFS + 백트래킹)으로 시도한다.

`DFS(k)`는 "현재 피로도가 k일 때, 아직 안 간 던전들 중에서 갈 수 있는 곳을 골라 이어서 탐험했을 때 얻을 수 있는 최대 던전 수"를 반환한다.

* 아직 방문하지 않았고(`!visited[i]`) 현재 피로도로 입장 가능한(`k >= copied_dungeons[i][0]`) 던전 `i`를 찾으면, 방문 처리(`visited[i] = 1`) 후 피로도를 소모(`k - copied_dungeons[i][1]`)한 상태로 재귀 호출한다.
* 이때 `1 + DFS(...)`는 "이 던전 하나 + 이후 자식 경로들 중 최댓값"이 되고, 이 값과 지금까지의 `best`를 비교해 더 큰 값을 유지한다 (`best = max(best, 1 + DFS(...))`).
* 재귀에서 돌아오면 `visited[i] = 0`으로 되돌려 다른 순서(다른 분기)를 시도할 수 있게 백트래킹한다.
* 더 이상 갈 수 있는 던전이 없으면 for문이 그대로 끝나고 `best = 0`이 반환되어 재귀가 종료된다.

즉 각 노드(던전 조합 상태)에서 "자식들 중 최대 경로 + 자기 자신(1)"으로 최댓값을 계속 갱신하며 올라오는 구조.

## 막혔던 부분 / 실수

* 없음 — 던전 순서에 따라 결과가 달라진다는 점을 파악하고, 방문 배열을 이용한 백트래킹으로 모든 순서를 탐색하도록 구현

## 시간복잡도

* 시간: O(N!) (던전 개수 N이 최대 8이라 모든 순열을 시도해도 충분히 빠름)
* 공간: O(N) (재귀 깊이 및 visited 배열)
