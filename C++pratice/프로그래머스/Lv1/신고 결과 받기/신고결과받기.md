# 신고 결과 받기

* 링크: 프로그래머스 - 신고 결과 받기 (Lv.1)
* 난이도: Lv.1
* 카테고리: 해시

## 문제 요약

유저 아이디 목록 `id_list`와 신고 내역 `report`(각 원소는 "신고자 피신고자" 형식의 문자열), 정지 기준 `k`가 주어진다. 한 유저가 같은 사람을 여러 번 신고해도 1회로 처리하며, 신고당한 횟수가 `k`번 이상이면 해당 유저는 정지된다. 각 유저별로 자신이 신고한 사람들 중 정지된 사람의 수(= 정지 메일을 받는 횟수)를 구하기.

## 핵심 아이디어

먼저 `id[id_list[i]] = i`로 이름별 인덱스 자리를 저장해서, 이름만으로 `answer` 배열의 위치를 바로 찾을 수 있게 한다.

각 신고 내역을 처리할 때 `record[from]`이라는 `set<string>`에 `from`이 신고한 사람들을 모아두는데, `set`은 중복 원소를 자동으로 걸러주므로 같은 사람을 여러 번 신고해도 한 번만 저장된다. `record[from].insert(to).second`는 실제로 새로 삽입되었는지(즉 처음 신고하는 대상인지) 여부를 반환하므로, 이 값이 `true`일 때만(중복 신고가 아닐 때만) `freq[to]`(피신고자별 누적 신고 횟수)를 증가시킨다 — 이렇게 중복 신고를 걸러내면서 동시에 정확한 누적 신고 횟수를 센다.

모든 신고 내역을 처리하고 나면, `record`를 순회하며 각 신고자(`from`)가 신고한 대상들(`targets`) 중에서 `freq[to] >= k`(정지 기준을 넘긴 대상)를 찾을 때마다 `answer[id[from]]`을 1씩 늘린다. 이렇게 하면 각 유저가 신고한 사람들 중 실제로 정지된 사람 수만큼 결과가 누적된다.

## 막혔던 부분 / 실수

* 없음 — `set`으로 신고자별 피신고자 목록을 관리하면 중복 신고 방지와 "새로 신고한 대상인지" 판별을 `insert`의 반환값 하나로 동시에 처리할 수 있다는 점을 이용

## 시간복잡도

* 시간: O(R log R) (R = report 개수, `map`/`set` 연산이 로그 시간)
* 공간: O(N + R) (`id`, `record`, `freq` 저장)
