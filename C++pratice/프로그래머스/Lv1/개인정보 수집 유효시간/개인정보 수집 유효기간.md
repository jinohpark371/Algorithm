# 개인정보 수집 유효기간

* 링크: 프로그래머스 - 개인정보 수집 유효기간 (Lv.1)
* 난이도: Lv.1
* 카테고리: 구현

## 문제 요약

오늘 날짜 `today`, 약관별 유효기간 목록 `terms`(타입과 개월 수), 개인정보 수집 내역 `privacies`(수집 날짜와 약관 타입)가 주어진다. 각 개인정보에 대해 "수집일 + 유효기간(개월)"이 지나 파기해야 하는지 판별해서, 파기해야 하는 개인정보들의 번호(1-indexed)를 오름차순으로 구하기.

## 핵심 아이디어

먼저 `terms`를 순회하며 `term[type] = 개월 수`로 타입별 유효기간을 맵에 저장해둔다. 이렇게 하면 각 개인정보의 타입만으로 몇 개월짜리 유효기간인지 바로 조회할 수 있다.

날짜 비교를 연/월/일 단위로 직접 하면 월마다 일수가 달라 계산이 복잡해지므로, 문제 조건(모든 달을 28일로 계산)을 이용해 모든 날짜를 하나의 정수(총 일수)로 변환한다.

```
toDays(year, mon, day) = year * 12 * 28 + mon * 28 + day
```

이렇게 변환하면 "연/월/일"이라는 세 값을 하나의 정수로 표현할 수 있어서, 두 날짜의 선후 관계를 뺄셈이나 대소 비교만으로 바로 알 수 있다. 개월 수 차이도 `개월 수 * 28`을 더하는 것만으로 날짜에 반영할 수 있다(1개월 = 28일로 취급).

전체 흐름:

1. `today`를 파싱해서 `toDayDays`(오늘의 총 일수)로 변환
2. 각 `privacies[i]`에서 수집일과 타입을 파싱
3. 수집일을 총 일수로 변환한 뒤, 해당 타입의 유효기간(개월 수 × 28일)을 더해 파기 예정일(`expire`)을 계산
4. `expire <= toDayDays`이면(파기 예정일이 오늘이거나 이미 지났으면) 파기 대상이므로 `answer`에 번호(`i + 1`) 추가

이렇게 모든 날짜를 같은 단위(일)로 맞춘 정수로 바꿔버리면, 날짜끼리의 비교가 단순 정수 비교로 끝난다.

## 막혔던 부분 / 실수

* 없음 — 문제에서 모든 달을 28일로 고정한다는 조건을 이용해 연/월/일을 하나의 정수(총 일수)로 환산하면, 달마다 일수가 다른 것을 신경 쓸 필요 없이 날짜 비교와 개월 수 더하기를 모두 정수 연산으로 처리할 수 있음

## 시간복잡도

* 시간: O(T + P) (T = terms 개수, P = privacies 개수, 각 항목을 한 번씩만 순회)
* 공간: O(T) (`term` 맵)
