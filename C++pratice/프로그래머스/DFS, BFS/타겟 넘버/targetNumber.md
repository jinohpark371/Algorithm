# 타겟 넘버

* 링크: 프로그래머스 - 타겟 넘버 (Lv.2)
* 난이도: Lv.2
* 카테고리: DFS, BFS

## 문제 요약

숫자 배열 `numbers`가 주어진다. 각 숫자 앞에 `+` 또는 `-`를 붙여서 모두 더한 값이 `target`이 되는 경우의 수를 구하기. 숫자는 주어진 순서대로 하나씩만 사용해야 한다.

## 핵심 아이디어

각 숫자마다 `+`를 붙이거나 `-`를 붙이는 두 가지 선택지가 있으므로, 첫 번째 숫자부터 시작해서 매 단계(`depth`)마다 두 갈래로 뻗어나가는 이진 트리 형태로 전체 경우의 수를 만든다.

`DFS(sum, depth, target)`는 "지금까지 `depth`개의 숫자에 부호를 붙여서 더한 결과가 `sum`"이라는 상태를 나타낸다.

* `depth == n`(모든 숫자를 다 사용함)이면 리프 노드에 도달한 것이므로, 이때의 `sum`이 `target`과 같은지 확인해서 같으면 `answer`를 1 증가시키고 재귀를 종료한다.
* 아직 다 사용하지 않았다면 현재 단계의 숫자(`copied_numbers[depth]`)를 더하는 쪽(`DFS(sum + num, depth + 1, target)`)과 빼는 쪽(`DFS(sum - num, depth + 1, target)`) 두 분기로 각각 재귀를 호출한다.

이렇게 각 깊이마다 정확히 두 개의 자식으로만 뻗어나가는 구조라서, 루트(첫 숫자)에서 시작해 깊이 `n`까지 내려가는 완전한 이진 트리를 DFS로 순회하는 것과 같다. 모든 리프(2^n개)를 다 확인해서 `target`과 일치하는 경우의 수를 센다.

## 막혔던 부분 / 실수

* 처음에는 재귀 안에 `for`문을 넣고 반복 시작 값을 `depth`로 둬서(마치 조합을 고르는 것처럼) 구현했는데, 이 방식은 재귀가 한 번 끝나고 돌아왔을 때 그 이전에 선택했던 숫자를 무시해버리는 문제가 있었다. 이 문제는 숫자를 "선택"하는 게 아니라 주어진 순서대로 전부 사용하면서 매번 부호만 고르는 것이므로, `for`문으로 시작 인덱스를 옮겨가며 부분집합/조합을 만드는 방식이 아니라, 각 깊이에서 정확히 두 번만(더하기/빼기) 재귀 호출하는 이진 트리 구조로 바꿔서 해결했다.

## 시간복잡도

* 시간: O(2^N) (각 숫자마다 두 분기로 나뉘므로 리프 노드 수가 2^N)
* 공간: O(N) (재귀 깊이)
