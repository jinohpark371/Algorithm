# 두 큐 합 같게 만들기

* 링크: 프로그래머스 - 두 큐 합 같게 만들기 (Lv.2)
* 난이도: Lv.2
* 카테고리: 큐 / 투 포인터

## 문제 요약

두 개의 큐 `queue1`, `queue2`가 주어진다. 한쪽 큐의 맨 앞 원소를 빼서 다른 쪽 큐의 맨 뒤에 넣는 연산을 반복해서, 두 큐의 원소 합이 같아지도록 만드는 최소 연산 횟수를 구하기. 불가능하면 -1을 반환.

## 핵심 아이디어

큐를 진짜로 `pop_front`/`push_back`하면서 구현할 필요 없이, 각 배열에서 "지금 맨 앞으로 간주할 위치"를 가리키는 인덱스(`queue1_idx`, `queue2_idx`)만 뒤로 이동시키면 큐의 동작을 그대로 흉내낼 수 있다. 어떤 원소를 다른 쪽으로 넘기고 싶으면, 넘기는 쪽 배열의 끝에 `push_back`으로 그 값을 추가하고 자기 쪽 인덱스를 한 칸 전진시키면 된다.

두 합(`sum1`, `sum2`)을 먼저 구해두고, 합이 다른 동안(`sum1 != sum2`) 더 큰 쪽에서 더 작은 쪽으로 맨 앞 원소를 하나 넘긴다.

* `sum1 < sum2`면 `queue2`의 맨 앞(`queue2[queue2_idx]`)을 빼서 `queue1`에 붙이고, 두 합을 그만큼 갱신한 뒤 `queue2_idx++`.
* 반대면 `queue1`의 맨 앞을 빼서 `queue2`에 붙이고 `queue1_idx++`.
* 매 연산마다 `answer`를 1씩 늘린다.

이렇게 "큰 쪽 → 작은 쪽"으로만 값을 넘기면 두 합의 차이가 매번 줄어드는 방향으로 움직이므로, 합이 같아지는 가장 빠른 경로를 따라가게 되어 최소 연산 횟수가 구해진다.

## 막혔던 부분 / 실수

* 이 반복이 언제까지 가능한지(연산 횟수의 상한선)를 정하는 게 애매했다. 큐 인덱스(`queue1_idx`, `queue2_idx`)가 각자 한 바퀴를 넘어 계속 전진한다는 게 "모든 경우를 다 시도해봤다"는 뜻이긴 한데, 정확히 몇 번째 반복에서 더 이상 답이 없다고 확정할 수 있는지를 엄밀하게 따지기는 어려웠다. 그래서 정확한 한계를 유도하는 대신, 두 배열의 전체 원소 개수(`n`)의 두 배(`2 * n`)를 넉넉한 상한선으로 잡고, `queue1_idx`나 `queue2_idx`가 이 값을 넘으면 더 이상 가능성이 없다고 보고 -1을 반환하도록 어림잡아 처리했다.

## 시간복잡도

* 시간: O(N) (인덱스가 각각 최대 2N번 전진하고 종료)
* 공간: O(N) (큐에 추가되는 원소들)
