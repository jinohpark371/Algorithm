# 이중우선순위큐

* 링크: 프로그래머스 - 이중우선순위큐 (Lv.3)
* 난이도: Lv.3
* 카테고리: 우선순위큐

## 문제 요약

`I 숫자`(삽입), `D 1`(최댓값 삭제), `D -1`(최솟값 삭제) 연산이 순서대로 주어진다. 모든 연산을 처리한 뒤 큐에 남아있는 값 중 최댓값과 최솟값을 구하기 (비어있으면 0, 0).

## 핵심 아이디어

최댓값용 max heap과 최솟값용 min heap 두 개를 각각 따로 두되, 두 힙이 "같은 데이터 집합"을 보고 있다는 걸 보장하기 위해 값별 개수를 세는 `cnt` map을 공유 상태로 둔다.

한쪽 힙에서 삭제가 일어나면 실제로 그 값을 힙에서 pop함과 동시에 `cnt[값]`을 감소시킨다. 그런데 반대쪽 힙에는 그 값이 여전히 남아있으므로(직접 pop하지 않았으므로), 나중에 반대쪽 힙의 top을 확인할 때 `cnt[top] <= 0`이면 "이미 다른 쪽에서 삭제된 값이 아직 지워지지 않고 남아있는 것"이라고 판단하고 그냥 pop해서 없는 값으로 처리한다(이때는 `cnt`를 추가로 감소시키지 않음 — 이미 삭제 처리된 값이므로).

이렇게 하면 두 힙을 물리적으로 매번 동기화하지 않고도, `cnt` map을 통해 "논리적으로 같은 집합"을 유지하는 lazy deletion 구조가 된다. top을 꺼내기 전에 항상 `cnt[top] <= 0`인 죽은 값들을 먼저 걸러내는 while문이 이 구조의 핵심.

## 막혔던 부분 / 실수

* 없음 — 두 힙이 별개의 자료구조라 삭제가 한쪽에만 반영된다는 점을, `cnt` 공유 카운트와 lazy deletion(꺼낼 때 죽은 값 걸러내기)으로 해결

## 시간복잡도

* 시간: O(n log n) (연산 n개, 각 힙 연산이 O(log n))
* 공간: O(n)
